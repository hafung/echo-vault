# Echo Vault 使用与维护指南

[English](guide.md) | **简体中文** · [返回首页](../README.zh-CN.md)

这里介绍来源兼容、搜索规则、完整备份与恢复，以及开发和维护命令。

## 使用

```bash
cd echo-vault
pnpm start
```

完成构建后，打开 **http://localhost:8765**，点击右上角「同步对话」导入可读取的记录。同步期间可以继续搜索和阅读。

页面保持打开时，距上次同步完成约 5 分钟后自动发起增量同步；打开或切回页面时也会检查是否到期。多个标签页共用服务端的时间检查，正在同步时不会重叠启动；手动同步仍可随时发起。自动同步完成会更新列表和数量，不弹出成功提示。关闭全部页面后不再发起自动同步，已启动的任务继续完成；浏览器挂起、电脑休眠时计时可能延后，恢复页面后会检查补同步。更频繁地收录可降低桌面 Chat 缓存在导入前被清理的风险，已经被清理的内容仍无法从缓存恢复。

开发或重新构建需要 Node.js 22+、pnpm、Go 1.26+：

```bash
pnpm install
pnpm build
pnpm start
```

独立运行：`./bin/echo-vault`；指定端口或数据路径：`./bin/echo-vault --port 8765 --data /path/to/echo.sqlite`。默认数据路径相对于运行目录，启动前应进入本项目。

一键启动：在 Windows 资源管理器中双击项目根目录的 `Start Echo Vault.cmd`，可以放一个该文件的快捷方式到桌面。脚本识别 `\\wsl.localhost\发行版\…` 和 `\\wsl$\发行版\…` 路径，并在对应 WSL 项目目录启动 Linux 可执行文件；普通 Windows 目录则使用 `bin\echo-vault.exe`。启动窗口负责保持服务运行，可最小化。Linux / WSL 也可运行 `bash scripts/start-echo-vault.sh`；`--open-browser` 会启动后打开浏览器，已有 Echo Vault 服务时仅打开页面。启动脚本不会安装依赖、自动构建或设置开机启动。

首次启动时窗口保持运行，保留或最小化即可；重复双击时只打开已有服务的页面，新启动窗口会正常退出，不会停掉原服务。若启动失败，窗口会暂停并显示错误。CMD 从 WSL UNC 路径启动时可能先提示「UNC 路径不受支持，默认值设为 Windows 目录」；这只是当前目录的提示，入口仍通过绝对路径调用脚本，再用 `wsl.exe --cd` 进入正确的 Linux 项目目录。入口会清理这条提示并显示运行说明。

开发前端：先运行 `pnpm start`，再运行 `pnpm dev`，打开 http://localhost:5178。

## 数据来源与完整性

- 自动发现当前用户、其他可读取的 WSL 用户、Windows 挂载盘用户的 `.codex`；同时扫描 `sessions` 与 `archived_sessions`。
- `.codex/session_index.jsonl` 与 `state_*.sqlite` 提供标题、路径、模型和归档信息；新版 `thread_history*.sqlite` 补充数据库历史及未落盘的条目。
- 兼容旧版 `response_item`、新版 `item_completed` 及二者混合的 JSONL。通过稳定 ID 与相邻镜像正文去重，保留真实重复提问。进展、工具调用、公开推理摘要及上下文可折叠阅读。
- 原始文件只通过 `os.Open` 和 `Stat` 读取。源 SQLite 先复制主文件和 WAL，验证复制期间两者未变化，再让 SQLite 读取临时副本。**绝不打开源数据库执行 SQLite 操作，也不接触源 SHM、认证文件、浏览器 Cookie。**
- 原始 JSONL 的完整字节以压缩块保存到档案数据库；相同原始块按内容哈希共用存储，所有逻辑版本保留；损坏的完整行保留原始字节并报告，尚未写完的最后一行在下次同步重试。加密推理原文保留，但无法解密展示。
- 检查点与对应正文、原始块在同一事务提交。进程中断后可重试。新版历史数据库先检查条目水位，仅解析变化的正文与附件。文件未变化直接跳过，纳秒时间戳使用精确整数比较；追加文件校验前缀与检查点尾部后继续读取。手动完整扫描可重新检查中间内容。
- 文件删除、文件截短、来源离线、ChatGPT 导出里删除节点，都不会删除已有消息。源条目自身更新时更新当前展示内容，之前导入的原始事件版本仍然保留。
- 图片的嵌入数据与可读取的本地图片复制、按 SHA-256 去重保存于 `assets`；未找到的附件保留引用。不会自动从远程 URL 下载图片。
- 自动发现 Windows ChatGPT Desktop 的 Chat 模式 HTTP 正文缓存（包括 WSL 挂载的 Windows 用户目录）。读取 Chromium blockfile 活动索引，仅解析 ChatGPT 会话响应，支持 Brotli、gzip、deflate 和未压缩正文。缓存只读，解析时复核所选响应字节，未写完或变化的响应报告提示并在下次同步重试。可在「数据与来源」手动添加 `…\Default\Cache\Cache_Data` 目录。
- 缓存的完整 `mapping` 与分页 `messages` 均可导入；分页按稳定消息 ID 合并并按时间排序。只收录已缓存的消息，其他分支或较早分页可能缺失；发现不完整分页时报告提示。在桌面应用打开对话并向前翻阅历史后再次同步，可补录新增缓存；缓存被清理后，已收录的正文与原始 JSON 仍保留。不会将只有标题的会话目录当作正文，也不会读取认证文件或 Cookie。
- 尚未连接 ChatGPT 云端；完整历史仍可在「数据与来源」导入官方 `conversations.json` 或包含该文件的 ZIP，也可添加导出路径。导出保留全部分支，非当前分支带标记；与桌面缓存按会话和消息 ID 合并。云端未导出、未被应用缓存的正文不能凭本地索引恢复。
- Windows 路径可直接填写 `C:\Users\…\.codex`、`D:\…\conversations.json`，应用在 WSL 中转换为 `/mnt/c/…`。其他 WSL 发行版如果未挂载，需要先提供可读取路径。

## 搜索和阅读

- 项目空间按项目内最近一次对话更新时间排序，最新项目在前。默认不选择项目；点击项目限定搜索范围，再次点击同一项目取消选择，顶部搜索恢复为跨项目搜索，提示文字同步显示范围。
- 项目右侧和对话阅读区右上角可隐藏 / 恢复。「项目空间」旁的眼睛图标控制「显示隐藏 / 归档」，默认关闭，开启时高亮，打开后才能在列表和搜索中看到隐藏记录与源端归档的对话。隐藏项目也隐藏后续同步进来的该项目对话；本地隐藏 / 恢复选择独立保存，增量同步、完整扫描和源端归档变化都不会覆盖，不删除正文、索引、附件或原始记录。导航数量随可见范围变化，完整备份始终包含所有数据。
- 全局、跨项目、按设备和应用筛选。支持收藏、日期范围、最近 / 最早排序，以及当前对话搜索与上下命中定位。
- 对话阅读区的删除按钮需要二次确认，删除本地会话、正文、搜索索引、原始记录及独占附件，共用数据保留，原始来源不变。不提供项目删除按钮；删光会话的项目自动从导航消失。删除标记保存在档案中并随完整备份保留，重启后增量同步仍跳过该会话，包含镜像或改名后的同 ID 来源。完整重新扫描仅在重新读取到该会话时清除其删除标记并收录，不可用来源的删除标记继续保留。
- 多个空格分隔的关键词按 AND 搜索；双引号表示完整短语。输入按字面值处理，不开放 SQL 或 FTS 表达式。
- 三字符及以上走 FTS5 trigram；单字、双字使用独立字符及双字符索引。中文短词和英文子串均可检索。
- 完整正文压缩保存；搜索索引不重复保存正文内容。正文使用独立检索索引，默认搜索不扫描工具输出的命中。长 Base64 / 二进制块不建索引，原始内容完整保留。默认搜索用户与助手正文，可开启工具与上下文搜索。
- 列表按页获取；消息每次获取 30 条，连续阅读窗口最多 90 条，长消息先展示 24,000 字，可主动展开。图片懒加载。阅读字号、深浅主题本地记忆。项目导航右侧边框中间的按钮可收起 / 展开导航，桌面收起状态本地记忆。
- Markdown 经 DOMPurify 清理；脚本、内联样式和远程图片不会执行或自动加载。代码可复制，表格可横向滚动。
- 对话中的 Windows / WSL 文件路径、`file://` 链接和带磁盘路径的 localhost 链接按本地文件处理；相对文件链接以会话项目目录为基准。点击后确认打开文件 / 文件夹，也可打开所在文件夹；路径不存在时显示提示。WSL 通过 Windows 默认应用打开，普通外部网址仍直接在新标签页跳转。程序与脚本文件可打开所在文件夹。
- `Ctrl / ⌘ K` 全局搜索，`Ctrl / ⌘ F` 当前对话搜索，`↑ ↓` 切换对话，`Esc` 收起面板或清除搜索。

## 存储、备份与迁移

个人数据适合 SQLite：单文件迁移，事务和 WAL 隔离同步写入与阅读，FTS5 索引省去外部搜索服务。Go 使用不依赖 CGO 的 SQLite 驱动，支持直接交叉编译。

「数据与来源」中的两种备份方式都调用 SQLite 在线备份 API，导出备份开始时的完整一致快照，包含已提交的 WAL 内容。正文、收藏、项目与对话隐藏状态、搜索索引、完整原始块与已收录的本地附件全部保留，可单独迁移；未导入的源文件、无法读取的附件和云端未导出的对话不在档案中。直接复制正在运行的 `echo.sqlite` 主文件可能漏掉 WAL，优先使用应用中的备份按钮。

备份格式提供 **Zstandard · 快速压缩**（界面默认）、**Zstandard · 更小体积**（耗时更多）以及 **SQLite · 不压缩**。压缩得到标准 `.sqlite.zst` 文件，使用流式处理、最多四个压缩工作线程和帧校验和，不把整个数据库读入内存，解压后 SQLite 与备份快照逐字节一致。先生成一致快照，再无损压缩；界面分别显示复制与压缩的真实进度，完成后显示原始大小、备份大小、节省比例及总耗时。生成压缩备份期间，目标磁盘需要同时容纳完整 SQLite 临时快照与压缩文件；成功或失败后清理临时文件。

压缩减少保存和传输大小，但本机生成总耗时会增加压缩步骤。正文、原始日志本来已经压缩，图片通常也已压缩，因此不能保证把数 GB 档案缩小几倍；更小体积档也取决于内容。若目标是最快完成本机备份，使用不压缩 SQLite 并直接保存到目录；需要减少传输量时选择快速压缩。没有为减小备份而省略原始数据或派生索引。

- **备份到此目录**：填写目录后点击备份，位置保存在档案设置中；也可先点击「记住位置」。默认使用数据库旁的 `backups` 目录，支持 `D:\备份\EchoVault` 等 Windows 路径。程序直接在目标目录生成备份，不经浏览器传输，也不再从系统临时目录复制一次。每次使用独立文件名，保留已有备份；未完成的文件使用 `.partial` 后缀，完成写入后再改为 `.sqlite` 或 `.sqlite.zst`。
- **备份整个档案 · 下载**：后台生成完整快照后，通过浏览器流式下载，不把整个档案读进 JavaScript 内存。生成的下载文件保留 1 小时；开始下一次备份会替换上一份临时下载文件。服务重启后需要重新生成下载备份。
- 点击立即显示启动状态，复制期间显示真实百分比、已复制大小与耗时，完成后显示保存路径或再次下载按钮，失败显示原因并允许重试。关闭面板或刷新页面不会取消后台任务；关闭程序会中断任务。
- 同时只运行一个界面备份任务，避免重复点击产生多个大副本。复制固定快照，期间仍可同步与阅读；不会因同步新增内容反复从头复制。更大的档案主要受磁盘读写与可用空间限制，项目数、对话数不限制导出，也不会截断内容。

恢复：在「数据与来源 → 恢复完整档案」填写本机 `.sqlite` / `.sqlite.zst` 路径，或点击「选择完整备份」上传。大文件推荐本机路径，不经浏览器传输。程序在当前数据库旁的 `restored` 目录恢复为独立 SQLite，验证 Echo Vault 表结构及 SQLite `quick_check`，完成后显示新文件位置和可复制的启动命令。停止当前服务，再执行该命令切换到恢复的完整档案；当前文件不会被覆盖，也不会将两个档案合并。后台复制 / 解压与验证期间可以继续阅读，刷新后再次打开面板可以查看状态；停止服务会中断未完成的任务。界面恢复上传支持超过 512 MB 的备份，限制为 1 TB；JSON / ZIP 来源导入仍限制 512 MB。

也可离线恢复到不存在的新文件（拒绝覆盖）：

```bash
./bin/echo-vault --restore /path/echo-vault.sqlite.zst --data /new/path/echo.sqlite
./bin/echo-vault --data /new/path/echo.sqlite
```

未压缩的旧版 SQLite 备份可直接用 `--data` 启动，也可通过上面入口恢复。若 SQLite 旁仍有非空 WAL，请使用应用在线备份后再恢复，避免遗漏已提交数据。既有来源路径可能在新设备不可用，可以重新添加，已有历史仍可读。`data/imports` 和上方 ChatGPT「导入文件」只用于原始 JSON / ZIP 导出与后续重试，已成功导入内容保存在数据库中。

原始日志含大量图片和重复工具输出，因此完整原始事件与附件占主要存储空间；档案文件并非只有聊天文字。SQLite 最大容量远超个人会话的合理增长，不需要数据库集群。

维护命令（先停止正在使用同一档案的服务；自定义档案请附加 `--data /path/to/echo.sqlite`）：

```bash
./bin/echo-vault --sync-only         # 手动增量同步
./bin/echo-vault --sync-only --full  # 完整扫描，保留已有历史
./bin/echo-vault --reindex           # 重建全部派生搜索索引
./bin/echo-vault --index-dialogue    # 仅重建正文检索索引
./bin/echo-vault --deduplicate       # 原始块按内容去重，保留所有版本
./bin/echo-vault --compact           # SQLite VACUUM，整理独立档案存储
```

Windows 可执行文件构建：

```bash
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 GOTOOLCHAIN=local go build -buildvcs=false -trimpath -ldflags="-s -w" -o bin/echo-vault.exe .
```

把可执行文件与备份的 SQLite 带到新机器即可运行；运行时不需要前端构建目录或 Go 编译器。

服务仅监听 `127.0.0.1`，验证 Host，写接口校验同源和自定义请求头。不连接模型 API，不上传对话，不收集遥测。Linux / WSL 数据库默认权限为 0600，新目录为 0700。此版本没有远程账户系统，适用于本机个人使用。

## 验证

```bash
pnpm test       # 增量、尾行、截断/删除保留、混合格式、镜像去重、源数据库不变、中文搜索、ZIP 分支、备份 WAL
pnpm test:links # 本地路径识别、localhost 磁盘路径、外部 URL 与 Markdown 链接
pnpm test:e2e   # Chromium：桌面/手机、搜索定位、筛选、收藏、导出、深浅主题、同源边界
```

Go 测试前需先构建前端，因为服务会内嵌 `dist`。浏览器测试需先启动应用并安装 Playwright Chromium；部分测试依赖包含 Windows / WSL 来源和长对话的已导入数据，请使用可丢弃的测试档案。可通过 `ECHO_TEST_URL` 指定测试地址、`ECHO_CHROMIUM` 指定已有 Chromium 路径。截图输出到 `artifacts/`，个人档案、附件、可执行文件与截图均不进入版本控制。

参考：[SQLite FTS5](https://www.sqlite.org/fts5.html)、[SQLite WAL](https://www.sqlite.org/wal.html)、[SQLite 在线备份](https://www.sqlite.org/backup.html)、[Zstandard](https://facebook.github.io/zstd/)、[ChatGPT 官方数据导出](https://help.openai.com/en/articles/7260999-exporting-your-chatgpt-history-and-data)。
